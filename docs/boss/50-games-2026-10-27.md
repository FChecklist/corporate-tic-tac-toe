## 8. RISKS AND TRAPS found
* Tic Tac Toe is a mailbox design: the server stores moves with its own stamp and never runs clocks or the bracket (docs/RULES.md section I). So the late move is DECIDED by the server stamp but the late tap is still STORED; every phone ignores it (the engine plays the clock-out first). Making the server refuse and store nothing would mean running the bracket on the server (later-round start times come from the phones). Not done on purpose; the owner should be told that "records nothing" is true for the game result, not for the mailbox row.
* The old S07 scenarios click the move-clock chips; they are hidden now (zc-hide). kit.mjs was patched to use `el.click()`; other scenario files that click chips directly would hang.
* z.css has a landscape rule that puts every `.zapp` child in column 2 (an empty left column would appear for the new `.tlayout`); ttt.css overrides with `.zapp:has(.tlayout){display:block}`. The size scenario S14 checks "no empty left column".
* A stray duplicate waiting script of mine once existed (pid 19624) and would have re-run the falsification later; it was killed. Do not launch scripts with a trailing `&` inside a tool call (they die or double up); use run_in_background.
* Tool bugs: bash `git` shim truncates; snip filter hides long output; python3 here is Windows Python (use Windows paths for open()); PowerShell 5.1 has no `&&`.
* The heavy lock changed protocol during the day: first a file (name + time), later a directory (mkdir/rmdir). Check which one exists before touching it.
* Earlier mistakes (already fixed): a bad `git checkout --` lost hand-resolved merges (redone); name-only join removed by Tambola join logic (restored with `nameOnly` flag); device proof had been gated by `checkinRequired` (made unconditional); build.mjs listed nonexistent files.
* Bingo claim step is a rule change; old published Bingo games must keep working with the old rule.
* Mockups are private artifacts: the owner must open them via Share; I verified only script syntax of the mockups, never a rendered view.
