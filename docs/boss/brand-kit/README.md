# Corporate Games brand kit (the ONE canonical look)

Folder: `C:\ct\test-sites\corporate-brand-kit` (its own git repo; not a game repo; nothing here is deployed). Kit version: see `VERSION` in `build.py`.
Every Corporate Games website and console takes **identical copies** of a few files from here, so Corporate Tambola (housie.), Bingo, Tic Tac Toe, Snakes and Ladders, Luck by Chance, Lucky Draw, the master console and the home site look and feel the same.
The look is the home site (28 Oct 2026) and Corporate Tambola 1.6.6, unchanged. Plain-English rules for people: `BRAND.md`.

## What is in the folder

| Path | What it is | A site copies it? |
|---|---|---|
| `tokens.css` | colours (light and dark, four header themes), type scale, spacing, radius, shadows, the six game colours, the ten console step colours. GENERATED by `tools/make_tokens.py` | yes |
| `fonts.css`, `fonts/` | Inter and Fraunces, self-hosted (same bytes as the home site) | yes |
| `components.css` | website parts: header (six-item menu, theme dots), hero, trust list, game-day strip, cards, buttons, forms, tables, chips, footer. Classes start with `ck-` | yes |
| `console.css` | organizer console parts: top bar, ten colourful steps, status chips, tiles, live control bar. Classes start with `cs-` | consoles only |
| `brandkit.js`, `theme-init.js` | phone menu, theme dots, Dark/Light button; and the head script that applies the saved choice | yes |
| `logos/` | `<product>.svg` (taken exactly from the home sprite), `corporate-games-mark.svg`, `lockups/` (badge + CORPORATE + name, light and dark), `png/` (512, 192, 180, 32, maskable 192/512), `ico/` (16/32/48), `social/` (1200x630 SVG and PNG) | via `vendor.py` |
| `manifest/<product>.webmanifest` | PWA manifest per product | via `vendor.py` |
| `snippets/` | HTML to paste: `sprite.html`, `head-/header-/hero-/footer-<product>.html`, `trust.html`, `gameday.html`, `console-shell.html`, `forms.html` | paste |
| `demo/` | one page per product: header, hero, trust list, game day strip, footer, then a console step card; open `demo/index.html` | no |
| `_headers.example`, `checksum.test.ts.example` | the no-cache lines and the checksum test | paste |
| `build.py`, `CHECKSUMS.sha256`, `vendor-checksums.json` | checksum manifest | no |
| `tests/` | node tests and the plant-and-see-red script | no |
| `tools/` | generators and the screenshot script (developer only) | no |

## How a site vendors the kit (exact steps)

Replace `<product>` with `tambola`, `bingo`, `tictactoe`, `snakes`, `luck` or `draw`; `<public>` is the site's public folder (the folder Cloudflare Pages serves).

1. **Copy the files** (dry run first, then for real):
   ```
   python -I C:\ct\test-sites\corporate-brand-kit\vendor.py <product> <public>
   python -I C:\ct\test-sites\corporate-brand-kit\vendor.py <product> <public> --apply [--console] [--no-manifest]
   ```
   It copies `tokens.css fonts.css components.css brandkit.js theme-init.js` (+ `console.css` with `--console`), `fonts/*.woff2`, and the icons under the names sites already use: `icon-192.png icon-512.png icon-maskable-192.png icon-maskable-512.png apple-touch-icon.png favicon-32.png favicon.ico favicon.svg og-card.png`, and `manifest.webmanifest` (skip with `--no-manifest` if the site already has its own start_url; then only copy the colours: `background_color #FFFAF2`, `theme_color #0B3D91`). It prints the SHA-256 of each file for the checksum test. It never edits a page.
2. **Paste the page parts**: `snippets/sprite.html` right after `<body>`; merge `snippets/head-<product>.html` into `<head>` (stylesheets with `?v=N`, `theme-init.js` WITHOUT defer, icons, manifest, theme-color, og:image); replace the old header with `snippets/header-<product>.html`; use `hero-<product>.html`, `trust.html`, `gameday.html` on the landing page; replace the old footer with `footer-<product>.html`; before `</body>` add `<script src="/brandkit.js?v=N" defer></script>`. Put `class="ck"` on `<body>` (and `class="ck cs"` on console pages). `<html>` carries `data-theme="blue"`.
3. **Point the six menu links at the site's own pages.** Change only the `href` values in the header (How it works, Free demo game, Guide, Brochure, Refer & earn, Log in). Never change the six labels, their order, or the classes `demo` and `login`. The Corporate Games bar (`corporate-games-bar`) stays above the header, unchanged.
4. **Cache bust**: every `<link>`/`<script>` of a kit file has `?v=N`. Use the next number the site has not used yet and raise it whenever a kit file changes (Cloudflare Pages keeps files for hours).
5. **Service worker**: if the site has a `sw.js` that precaches files, add the kit files to its list and bump its version constant in the same commit, so installed phones fetch the new files.
6. **`_headers`**: add the lines of `_headers.example` (no-cache for the kit css/js and the manifest, long cache for `/fonts/*`; the Content-Security-Policy is the one all our sites already use).
7. **Checksum test**: copy `checksum.test.ts.example` into the site's tests, paste the hashes `vendor.py` printed. It fails if anyone edits a copy. To update later: change the kit, run `python -I build.py`, run `vendor.py --apply` again, update the pins.
8. Delete the site's own older header, theme-dot script and duplicate button/card CSS **only** from landing and console pages that now use the kit. Game screens that players use (tickets, boards) keep their own CSS; the kit does not touch them (all kit classes are `ck-`/`cs-`).
9. Check: serve the site, open it at 360, 390, 768, 1280 and 1920 wide, light and dark; no horizontal scroll; the browser console shows no CSP error.

Notes for particular sites:
- **Home site**: its own classes (`.btn`, `.card`, `data-theme=light|dark`) keep working next to the kit. The kit also understands the old `data-theme="dark|light"` on `<html>`, but new code should use `data-mode`. Use `data-theme="indigo"` to keep the home site's indigo.
- **Corporate Tambola (housie.)**: the header in `snippets/header-tambola.html` replaces the 10-item bar of 1.6.5/1.6.6 (no AI-assistant pill, Video, Pricing or WhatsApp in it); the theme dots are in the kit header; `theme.js` of Tambola (`ct-theme`: maroon/blue/emerald) uses the same storage key, so saved choices carry over.
- **Master console and the five consoles**: `console.css` plus `snippets/console-shell.html` show the structure (top bar with a status chip, payment strip, "X of 10" meter, step list, bottom tabs on a phone). Status chips: `<span class="cs-chip" data-s="draft|waiting|ready|playing|finished|cancelled|notstarted">` with the words Draft, Waiting for payment, Ready, Playing now, Finished, Cancelled, Did not start.

## Rules every site keeps (the tests enforce what a machine can check)

- **CSP-safe**: no inline `<script>`, no `style="..."`, no `<style>`, no inline event handlers. The sprite is inline SVG (allowed). Policy: `default-src 'self'; img-src 'self' data:; style-src 'self'; script-src 'self'; font-src 'self'`.
- **No outside request**: self-hosted fonts only (never Google Fonts), no CDN, no analytics in the kit.
- No file contains the banned word (see `BRAND.md`). English only. Strapline: "Online games for company events".
- Never edit a vendored copy: change the kit, rebuild, copy again.

## Changing the kit

1. Colours or type: edit the tables in `tools/make_tokens.py`, run `python -I tools/make_tokens.py`. Add any new text/background pair the CSS uses to `tests/contrast-pairs.json`.
2. A logo or a name: edit the table in `tools/make_logos.py` / `tools/make_snippets.py`, then `python -I tools/make_logos.py lockups`, `node tools/render_png.mjs` (needs the `sharp` library; set `SHARP=<folder>` if it is not at `C:/ct/ct/node_modules/sharp`), `python -I tools/make_logos.py ico`. Lockup and social-card words are turned into outlines with fontTools (set `BRANDKIT_PYLIB` to a folder with `fonttools` and `brotli`; developer tools, never shipped).
3. `python -I tools/make_snippets.py` (snippets, manifests, demo pages), raise `V` there and `VERSION` in `build.py` when css/js change.
4. `python -I build.py` (prints and writes `CHECKSUMS.sha256`, `vendor-checksums.json`; refuses an SVG that is not well-formed).
5. `node --test tests/kit.test.mjs` (22 tests: file hashes, SVG validity and no outside references, banned word, WCAG AA contrast of every token pair in light and dark for four themes, the six menu labels exact, CSP-safe, PNG/ICO/manifest sanity). `node tests/falsify.mjs` plants 20 faults in a temporary copy and demands the right test goes red.
6. Screenshots (real browser; take the single heavy lock first: `mkdir C:/ct/heavy.lock`, `rmdir` when done): `node tools/shots.mjs` writes `C:\ct\test-sites\data\ui\brand-kit\` (5 widths, light and dark, header/CSP/overflow checks).
7. Commit in this repo. Do not push; sites vendor from this folder.

## Known limits
- The numbers inside the Tambola, Bingo and Lucky Draw badges are text in system Arial (exactly as on the home site); every other word in a logo file is an outline.
- The header collapses to the phone menu below 1024 px so six pills, the name and the dots always fit on one row from 1024 px up.
- Lucky Draw is not built: its hero button says "Tell us you want it".
