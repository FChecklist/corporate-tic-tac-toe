# Spec 5 (owner-approved 2026-10-08): data retention for tournaments that are not played, rescheduling, and "Create a new one like this"

**Status for Corporate Tic Tac Toe (checked 2026-10-13).** Shared code (`unplayedPass`, `erasePersonal`, `credit`, clone) works as written, with "game" read as "tournament" and "guest" as "player". "Not played" means the host never pressed Start and nobody paid. Part B copies the sister product's settings; for a tournament only the parts that exist apply (see B2). "Not true yet" at the end lists the differences. Source of truth for what is deleted when: `docs/PRIVACY_AND_LIFECYCLE.md`.

Same style rules as specs 1 to 4 (owner non-technical; plain words; short sentences; no dropdowns; hints at most 2 sentences). E-mail only for Organizer and Host.

## A. Data rule for games that are not played

1. **Personal data of a game that did not start** (guest names and mobile numbers, people lists, waiting requests, personal links, Co-host name and mobile, brand logo is NOT personal) is erased within **24 hours after the game's scheduled END time** (for a tournament that never started use the same end estimate the lifecycle uses for a played one, `endBoundMs`: 6 hours after the scheduled start, `endBoundTtt`; erase at end + 23 h like the played-tournament deletion), unless the game was rescheduled (the clock follows the newest time) or a new game was created from it with "bring my people list" (the list then belongs to the new game and follows its clock; the old game's copy is erased as usual). Organizer and Host data stays (name, e-mail, mobile, payment and invoice records, per the existing 365-day rule; tax-law retention of invoices is for the owner's CA to confirm).
2. "Not played" = the tournament was never started (nobody paid, or the host never pressed Start). A tournament that started follows the existing rule (23 hours after the final), including one with zero players.
3. **Rescheduled games**: the clock follows the newest scheduled time; the data stays until that time + 24 hours (or, if the game is played, until 23 hours after it ends).
4. **No payment, no game (OWNER CORRECTION: there is NO separate 24-hour cut-off after the game time).** The game never starts without a payment confirmed by Razorpay. The Organizer, a Host or a Co-host can pay at ANY time until the guest data is erased (scheduled end + 23 h); a late payment unlocks the game (the sister product also started its numbers 2 minutes after confirmation; for a tournament the host presses Start). While unpaid: the **Organizer and Host see "Payment pending for this game"** (status pill and notice strip); **everyone else (guests, Co-hosts) sees "Waiting for the Organizer or Host to start the game."** on the ticket page / My page / big screen instead of any payment wording. These messages last until the game's end time and then for the 24 hours until the participants' data is deleted. After the erasure the old game is **closed**: nobody can join or pay; guests who open their link see "This game did not start. Your details have been erased."; the Organizer/Host see it as 'Did not start' with the button "Create a new game like this one".
5. **Time limit**: a game time can be set at most **30 days ahead** (server enforced, friendly message in the console, the AI path and the API); any number of reschedules inside that window.
6. **Game settings are not personal data**: for an expired or unplayed game the settings (occasion, size, prizes, brand name/colour/logo, brand moments, invite options, who-can-join) stay for 30 days after expiry so the Organizer or Host can reuse them; then they are forgotten like drafts today. Drafts never published: unchanged rule (30 days), plus any personal data erased as above.
7. **E-mails** (Organizer and Hosts only): a heads-up about 6 hours before the erasure ("Your game time has passed. Guest data will be erased at <time>. Tap to reschedule and keep it.") with a link that opens the game; after the erasure ("Your game did not start. We erased the guest list at <time>.", reuse the existing data-deleted mail). Idempotent, one of each per game.
8. **Wording** (everywhere): privacy text, terms/DPA/legal pages (through tools/make-legal-pages.mjs), the report PDF text, organizer guide, AI FACTS fact 4 and the trust page (`bun run tools/make-trust.ts`), the console 'After the game' step and its About line, and `docs/PRIVACY_AND_LIFECYCLE.md` and `docs/RETENTION.md` (the data timeline).
9. Tests: every rule (unplayed game erased at +24 h; played game unchanged; reschedule moves the clock; late payment inside/outside the window; 30-day limit; settings kept 30 days; e-mails sent once; Organizer/Host data untouched), with mutation checks.

## B. "Create a new game like this one" (Organizer and Host, equal rights)

1. A button **"Create a new game like this one"** on the game page (Check and publish step), on expired/cancelled/finished games, and in the games list. Not for Co-hosts.
2. It makes a **new draft with a new game id** and copies the settings that exist for a tournament: occasion/name, size (number of players), who can join, player-invite options and Co-host limit, brand strip. (The sister product also copied tickets, gap between numbers, rounds, prizes, brand moments and the lucky draw; a tournament has none of these. The format and the move clock are chosen at Start, so they are not copied.) It does **not** copy payment, status, guests, waiting requests, Co-hosts (their links are per game: add them again), or personal links. Hosts already work across games.
3. **The date and time must be chosen again** (never copied): the new game opens on step 1 with the date and time empty.
4. **People list**: if the old game's list still exists (before the erasure), offer a tick box "Also bring my people list from the old game" (reuses the existing reuse route; each person gets a new personal link); otherwise say calmly "The old guest list has been erased, so add your people again."
5. **"It confirms everything"**: after creating, the console shows the 'Check and publish' read-back of everything that was copied with a Change button for each part, and a short line "This is a new tournament. Nothing is paid or published yet." The Organizer or Host then publishes it (free) and pays from the Pay step like any new tournament: new price, new payment.
6. Server: `POST /api/z/{id}/clone {startRound?, withPeople?:boolean}` (master, Host) -> `{ok, id, openUrl, copied:[...], peopleCopied:n|0}`; atomic, validated with the same rules (30 days ahead, limits), the 10-draft limit applies, audit-logged, AI key 403 (a person must do it). Tests including that nothing personal or paid is copied.
7. Console wording (plain): button "Create a new game like this one"; after: "Your new game is ready to check. Pick the date and time, then publish."
