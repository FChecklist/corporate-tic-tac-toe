## The e-mail rule (applies everywhere, including the console wording)

- **Only the Organizer and the Host have an e-mail.** Everyone else (Co-host, participants) gives **name and mobile number only**. Never ask for, store or send anything by e-mail to anyone but the Organizer and Hosts. (The payer on the payment page gives name + e-mail for the invoice: that is the one exception, already built.)
- **No winners e-mail** (cancelled from the plan). Winners stay in the Organizer's report and in the console.
- The console must SAY this where people add people: on "Your team" and "Your guest list": *"Guests and Co-hosts need only a name and a mobile number. No e-mail is needed. Only the Organizer and Hosts have an e-mail."*
- E-mails that exist for Organizer + Host: the Host's own link (sent to the Host's e-mail when the Organizer adds the Host), reminders, the report link (Organizer only), "game cancelled" (Organizer + Host(s) + the payer), "your guests' personal data has been deleted" (Organizer + Host(s)).

## Phase 1 (server + console)

1. **Cancel a game** (Organizer and Host only; Host cancelling e-mails the Organizer).
   - Allowed: any time before the start time if unpaid; before the start time if paid. **Not allowed once the start time has passed and it is paid** (a friendly message: use End the game). Unpaid games may be cancelled any time (no money involved).
   - Console: three confirmations that get more serious each time (tap 1 "Cancel this game?", tap 2 shows what happens: guests told, refund amount, cannot be undone, tap 3 "Yes, cancel <game name>"). Server requires `confirmations: 3`.
   - `GET /api/z/{id}/cancel-preview` -> `{ canCancel, reason?, paid, refund: { paidInr, feeInr, refundInr, feeNote } | null }`.
   - `POST /api/z/{id}/cancel { confirmations: 3 }` -> `{ ok, cancelled: true, refund: {...}|null }`. Roles: master, host (+ platform owner).
   - After cancel: game shows to guests as "This game was cancelled by the organizer" (info/phone page/big screen), cannot be published or paid again, guests' names and numbers erased with the normal 23 h rule from the cancel time; keys/links keep working only to read the cancelled state.
2. **Refund** (only when paid and cancelled before the start time): refund = amount paid **minus** the payment-gateway charge. Make the charge a clearly named constant/env (`REFUND_FEE_RATE`, default `0.0236` = 2% + 18% GST on that fee) and show the exact numbers in the preview and the cancel e-mail. Refund goes back to the original payment method through the Razorpay refunds API when keys are configured; with no keys (today) record `refund_status='requested'` and e-mail the platform owner so they can process it in the Razorpay dashboard. Statuses: requested / processed / failed. A **GST credit note** is created for the refund (reuse the invoice machinery; same series rules; flagged draft when company details are incomplete). A referral partner's commission on that sale is voided (reuse the existing void). One refund per payment; idempotent. TEST mode: no Razorpay call; labelled test refund. Update `apps/web/public/terms.html` and `legal.html` (refund clause, plain words: cancel before start for a refund minus gateway charges; no refund once the start time has passed) and any sentence saying "no refunds after payment" (grep `refund`); keep the banned-claims tests green.
3. **Game starts only after Razorpay confirms the payment** (already built: signature + asking Razorpay + webhook). Add the soft state "Confirming your payment..." on the pay page and console status pill until confirmed; never mark Paid before confirmation. TEST mode excepted.
4. **Host e-mail**: `POST /api/org/host { label, email }` requires a valid `email` for a Host; store it on the key row (new column) and e-mail the Host their own link directly (not the Organizer). `GET /api/org/team` shows the Host's e-mail to the Organizer and Hosts. Retiring a Host revokes the key at once.
5. **Co-host name + mobile (no e-mail)**: `POST /api/org/cohost { label (their name), phone }`, phone required (valid mobile), stored sealed (same sealing as participants). The Co-host key is **bound to one game** (`eid`) and the Co-host's name and mobile are erased (key retired) when that game's participant data is erased (23 h rule) or when the game is cancelled. `GET /api/org/team?e=<id>` lists that game's Co-hosts (name, masked mobile).
6. **"Your guests' personal data has been deleted" e-mail** to the Organizer and the Host(s) when the automatic deletion runs, with the exact time (IST). Plain, calm wording. The existing manual-deletion mail stays.
7. **Late payment starts 2 minutes after payment** (sister product: the first number came 2 minutes after the payment was confirmed). For a tournament there is no number; the host presses Start once the payment is confirmed. How the shared "locked until paid" state behaves for a tournament has not been checked.

Console (Phase 1): Cancel game button (Organizer and Host) with the three confirmations and the refund numbers; "Confirming your payment..." state; Host e-mail field on Your team (required for a Host) and name + mobile for a Co-host (no e-mail field); the e-mail-rule sentence on Your team and Your guest list; **AI helper switch moved** into the AI Assistant strip as a small line ("My AI works in my web browser: hide guest names and numbers"), Organizer and Host only, off by default, removed from the top of every page and from Co-host views.

## Phase 2

8. **Chain**: every person's link carries the whole chain game -> Organizer -> Host -> Co-host -> participant level 1 -> participant level 2. Record who created each Co-host (`created_by`: Organizer or which Host) and give the Organizer and each Host their own invite link (so people they invite are traced to them). The report's "Who invited whom" tree starts at the Organizer and shows roles.
9. **Remove a person**: before the game: Organizer and Host (anyone), Co-host and participants (only their own invitees/chain); frees the place, stops their invite link, blocks the same phone from re-joining that game unless re-admitted; option "only this person" or "this person and everyone they invited". During the game: Organizer and Host only; the phone stops and shows "removed". For a tournament the removed player can no longer move and loses the board by the clock (the server refuses a removed seat); the seat and the match record stay, so the bracket does not change shape. Every removal is logged (who removed whom, when). A Host's removal/cancel e-mails the Organizer.
10. **Waiting room**: admission is only by clicking an invite link. Organizer setting with three modes: "Anyone with the link joins" (default), "The person who invited them approves", "Organizer and Host only". Approvers: Organizer and Host for everyone; a Co-host and a participant for their own invitees only. Pending requests do not use up places. Record **who approved** each person (shown in the console and report). Approvers see first name + last 4 digits of mobile. Guests waiting see a friendly message. People over an inviter's quota go to the Organizer/Host waiting room instead of a hard refusal. People on the Organizer's uploaded list are admitted when they click their link.

## Phase 3

11. **Brand strip on the player page**: organizer sets company name + accent colour + optional small logo (resized in the browser to <= 30 KB, stored with the tournament settings as a data URL: no outside request); shown at the top of the player page (`ttt.js` shows the name on the accent colour; the logo is not shown yet). A "Powered by" line is not built.
12. **Preview** for Organizer and Host (not Co-host): "See what players see" would open a sample player page marked PREVIEW with the brand strip. Not built for Tic Tac Toe: `preview.html` is the sister product's brand-moment tester.
13. **Pay link anyone can open** (no sign-in): Organizer, Host or Co-host creates it; the page shows only game name, date, price with GST and one Pay button, asks name + e-mail only; pays that game only; expires after 7 days or at payment; "Copy payment link" button next to the Payment status.
